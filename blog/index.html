bugfix

Fixed a relatively minor bug with Date formatting my blog post dates a day after the date in the markdown file. This is because the us-en locale's timezone defaults to LA (los angeles, not louisiana) time, so i had to set the .timeZone in the options list to UTC to fix.

building the website (and design considerations) pt. 1

There were quite a few things I want from my website, so I guess I'll use my second ever blog post to explain them.

Appearance. I wanted to capture the sleek minimalism of iOS 26's liquid glass look, so I went with a frosted glass look by creating a transparent div that applies a blur to the part of the background image it is over. The background image is temporary, but as of right now (08/23/26) it's a snowy forest. While it does match the color palette, it impacts readability quite a bit. Later, I want to apply different images and particles using Particles.js or something to each individual page of the website.

All the text is in a font called Atkinson Hyperlegible, a font that I believe should be the standard everywhere on the web. It's designed for maximum readability and accessibility. Additionally, almost all of the big, important text is lowercase. I want my website to have a very relaxed vibe to it, which I feel helps my website stand out.

Functionality. Obviously, my website isn't finished yet, but I'm ultimately trying to make it very concise and functional. When I think of a functional website, I think of McMaster-Carr's website. Even a first time user of McMaster-Carr's site can pretty quickly locate any part they want, without extreme page loading times and bloat.
This is something that I'm trying to replicate. I want everything in my website to load fast, and I want it to be easily navigatable. In order to do this, I have all of the subpages immediately visible upon first visiting the site, with the user's eyes drawn to them as they load in one by one. For the project tabs I will add different categories going from broad to narrow to make it easier to locate all of the projects I've done.

However, pure functionality is boring. This site should be extremely easy to navigate for employers, while for those who are really interested, I want there to be a lot of small details that make the site feel refined.

That's all I have for now. Sorry for typos or strange sentence phrasing, I'm kinda cranking these blog posts out and I want at least some information out before I continue.

august 15, 2026

test

This is the very first blog entry. I got inspired by geaux engineering and I thought it would be nice to have a website of my own, then I realized I should include a blog because all of the cool kids have one.

I'll be trying to implement everything without using frameworks or templates, because i think it will help my web development skills

My blog implementation is based off of this reddit thread where they talked about using markdown files to populate their blog. I did much the same. My code iterates through all of my posts (based on a manually filled out json file of all of my posts), then parses the markdown file and converts it into HTML. It creates each part of the blog post container and then uses the converted markdown file as the inner content.

I don't actually know if it's scalable, but this is all a learning excercise for now.
